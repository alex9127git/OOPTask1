# Повторяющиеся события

Первая аттестация по ООП: модель календаря с одиночными и повторяющимися событиями на Java 21.
Серия событий строится по правилу повторения от даты начала. Её можно развернуть в даты
на интервале и ограничить числом повторений или конечной датой. Отдельное вхождение можно
удалить или перенести, не трогая остальные, и можно найти ближайшее вхождение начиная с даты.

## Запуск

Нужны JDK 21 и Maven.

Демонстрация:

```bash
mvn compile exec:java
```

Тесты:

```bash
mvn test
```

Документация в `target/reports/apidocs`:

```bash
mvn javadoc:javadoc
```

## Модель

```
src/ru/vsu/cs/nagajcev_a_a/
├── Main.java                  консольная демонстрация
├── event/                     события
│   ├── Event                  sealed: SingleEvent | RepeatingEvent
│   ├── SingleEvent            одиночное событие
│   ├── RepeatingEvent         серия: развёртка, перенос, удаление, ближайшее вхождение
│   ├── EventId                record-идентификатор события
│   └── DateConflictException  два вхождения на одну дату
├── repeat/                    правила повторения
│   ├── RepeatRule             интерфейс правила
│   ├── NDayRepeat             каждые N дней
│   ├── WeekdayRepeat          по указанным дням недели
│   ├── NMonthRepeat           каждое N-е число месяца
│   ├── CustomMonthRepeat      «второй вторник», «последняя пятница» месяца
│   ├── CustomMonthRepeatPattern  перечисление: FIRST…FOURTH, LAST…FOURTH_TO_LAST
│   ├── NYearRepeat            раз в N лет
│   └── InvalidRepeatRuleException  недопустимые параметры правила
└── endRule/                   условия окончания серии
    ├── EndRule                sealed: Never | AfterCount | Until
    ├── Never                  без окончания
    ├── AfterCount             после N вхождений
    └── Until                  до даты включительно
```

### Правила повторения

`RepeatRule` — интерфейс с единственным полиморфным методом `calculateNextDate(start, k)`.
Метод возвращает дату вхождения номер `k` (с нуля) для серии, начинающейся с `start`.
Вхождения всегда считаются от начала серии, а не от предыдущего вхождения. Иначе
ежегодное событие от 29 февраля после первого невисокосного года навсегда «съехало» бы на 28-е.

Краевые случаи календаря:

- **31-е число в коротком месяце.** `NMonthRepeat(31)` в апреле приходится на 30-е,
  в феврале на 28-е или 29-е, а в следующем месяце возвращается к 31-му без накопления сдвига.
- **29 февраля.** `NYearRepeat` от 29.02 в невисокосные годы даёт 28.02,
  в високосные снова 29.02.

### Серия событий

Вхождения серии нумеруются с нуля по порядку исходных дат. Номер закреплён за вхождением
и после переноса, поэтому все операции над одним вхождением работают по номеру.

| Операция | Метод `RepeatingEvent` |
|---|---|
| Развёртка на интервал `[from, to]`, обе границы включительно | `getSeries(from, to)` |
| Ограничение числом повторений или конечной датой | конструктор с `EndRule`, `setEndRule` |
| Перенос одного вхождения и его отмена | `addException(k, date)`, `removeException(k)` |
| Удаление одного вхождения и восстановление | `deleteOccurrence(k)`, `undeleteOccurrence(k)` |
| Ближайшее вхождение в дату или позже | `nextFrom(date)` → `Optional<LocalDate>` |

Принятые соглашения:

- Два вхождения одной серии никогда не стоят на одной дате. Перенос на занятую дату,
  отмена переноса или восстановление, когда исходная дата уже занята, бросают `DateConflictException`.
  Состояние серии при этом не меняется.
- `AfterCount` считает вхождения по номерам. Удалённое вхождение тоже расходует счётчик,
  а перенос не продлевает серию.
- `Until` сравнивает исходную дату вхождения, поэтому последнее вхождение можно перенести
  за конечную дату.
- Смена правила повторения сбрасывает переносы и удаления: при новом правиле те же номера
  приходятся на другие даты.

### Равенство событий

Событие — сущность. При создании оно получает уникальный `EventId` (record с положительным номером),
и `equals`/`hashCode` события определяются только им. Название, дату, правила, переносы и удаления
можно менять, и событие остаётся тем же, в том числе в `HashSet` и `HashMap`. Два события
с одинаковыми полями, созданные отдельно, — разные события.

### Исключения

| Исключение | Когда | Почему непроверяемое |
|---|---|---|
| `InvalidRepeatRuleException` | интервал ≤ 0, число месяца вне 1..31, пустой список дней недели | неверные параметры правила — ошибка в вызывающем коде |
| `DateConflictException` | операция поставила бы два вхождения на одну дату | вызывающий может заранее проверить дату через `getSeries` |
| `NullPointerException` | `null` вместо даты, правила или условия окончания | ошибка в вызывающем коде |
| `IllegalArgumentException` | отрицательный номер вхождения, перенос несуществующего или удалённого вхождения, `AfterCount` ≤ 0 | ошибка в вызывающем коде |

Демонстрация ловит `InvalidRepeatRuleException` и `DateConflictException` и печатает понятное сообщение.

### Java 21

- `sealed` иерархии `Event` и `EndRule`;
- `record` для `EventId`, `Never`, `AfterCount`, `Until` с проверкой в компактном конструкторе;
- `switch` с сопоставлением с образцом по `EndRule` в серии и по `Event` в демонстрации.

## Тесты

Более 200 тестов на JUnit 5 в `test/`:

- `NDayRepeatTest`, `WeekdayRepeatTest`, `NMonthRepeatTest`, `CustomMonthRepeatTest`, `NYearRepeatTest` —
  правила повторения, краевые случаи календаря (31-е число, 29 февраля, переход через год), исключения;
- `SeriesTest` — развёртка, переносы, конфликты дат, ограничения, удаление, ближайшее вхождение;
- `ContractTest` — контракт `equals`/`hashCode` для `EventId` и `Event`, поведение в хеш-коллекциях.

Кроме отдельных сценариев, многие тесты сверяют результат с независимым расчётом
на всех правилах повторения и большом числе дат.
